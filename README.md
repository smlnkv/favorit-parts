# Поиск автозапчастей

Интеграция с API "Проценка" (Favorit Parts). Приложение реализует двухэтапный подбор: сначала поиск производителей по артикулу, затем получение аналогов и предложений выбранного бренда.

## Запуск

Для работы нужен Node.js версии 22.12 или выше (проверялось на 24).

```bash
npm install
npm run dev
```

Приложение откроется на `http://localhost:3000`.

## Стек

- React 19
- Redux Toolkit
- React-Bootstrap (Bootstrap 5)
- Vite 8
- fetch-layers (для транспорта)

## Особенности интеграции с API

Документация API имеет несколько нюансов, которые учтены в коде.

**Ключ доступа.** В `src/api/client.js` лежит константа `CLIENT_KEY` с ключом из документации. API возвращает ошибки с HTTP 403 и текстом вида `{"error": "Invalid access key"}`, если ключ неверный.

**Формат ошибок.** API отдает ошибки нестандартно: HTTP 403 с `Content-Type: text/plain`, а внутри JSON `{"error": "..."}`. В `fetch-layers` передается функция `parseErrorBody`, которая вытаскивает текст ошибки в `ApiError`.

**Цена.** Согласно документации, поле `goods.price` использовать нельзя. Цена берется только из `warehouses[].price`. В заголовке позиции показывается минимальная цена (`minPrice`), рассчитанная по складам, где `stock > 0`. Если остатков нет, цена не выводится (показывается прочерк).

**Остатки.** Поле `count` в ответе API уже содержит сумму остатков по всем складам. Приложение использует его как есть и не пересчитывает.

**Невозвратные позиции (улучшение).** Чекбокс "Показывать невозвратные позиции" добавляет параметр `info=on`. Флаг `notRefund` приходит на двух уровнях: на самом товаре и на конкретном складе. В интерфейсе это отображается сводным бейджем на заголовке позиции (если товар или хотя бы один склад невозвратный) и отдельной колонкой в таблице складов. Если чекбокс выключен, запрос не шлет `info=on`, колонка и бейдж скрываются. Яркий пример - бренд ASAM: сам товар возвратный, но часть складов возврат не принимают.

**Пустой ответ (улучшение).** Если товар не найден, API возвращает HTTP 200 с массивом, содержащим одну пустую структуру (`goodsID: "0000..."`, пустой `brand`). Приложение отфильтровывает эту заглушку и показывает "Ничего не найдено".

**Этап 2 (Аналоги).** Ответ на втором этапе отличается от первого: приходит `goods[0]` с вложенным массивом `analogues`. Функция `normalize.js` разворачивает это в плоский список, помечая исходный товар флагом `isOriginal`, и вычисляет для каждой позиции `minPrice` и сводный флаг `hasNonRefundable`.

**Почему номер берется из списка.** При клике на бренд в API уходит `number` из выбранного элемента списка, а не из поля ввода. Это важно, так как артикулы могут отличаться: пользователь ищет `01089`, а у бренда GLASER номер детали `H01089-00`.

**Неиспользуемые поля.** При передаче `info=on` API возвращает поля `brand_quality`, `defect` и `sale`. Их семантика не документирована, в требованиях их нет, поэтому они игнорируются.

## Решения

**Транспорт.** Для запросов используется библиотека `fetch-layers`. Она закрывает три задачи: разбор нестандартного формата ошибок через `parseErrorBody`, автоматические повторы при сетевых сбоях и 5xx (`withRetry`), и отмену запросов через `AbortSignal`. Если убрать библиотеку, логика приложения не изменится, переписывать придется только `src/api/client.js`.

**Состояние.** Используется Redux Toolkit.

**Отмена запросов.** Ввод артикула имеет дебаунс 500 мс. При быстром вводе или клике по двум брендам подряд предыдущий запрос отменяется.

## Проверка работоспособности

1. Введите `01089` в поле артикула. Появится список из 10 брендов.
2. Введите `ZZZZZZZZ`. Появится сообщение "Ничего не найдено".
3. Кликните на `ASAM`. Откроется таблица с оригиналом (на трех складах) и аналогами.
4. Кликните на `GLASER`. Откроется таблица с оригиналом и аналогами (у некоторых цена будет с прочерком из-за отсутствия остатков).
5. Поставьте галочку "Показывать невозвратные позиции" и проверьте бренд `ASAM` - появится бейдж и колонка со значениями "да/нет".
